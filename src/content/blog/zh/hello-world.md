既然是第一篇，就写写它自己发布在什么东西上。

## 为什么用静态站

这里的一切都是 Markdown 在构建时编译成 HTML。没有服务端，没有数据库，也没有前端框架 —— 真正发到浏览器的
JavaScript 只有主题切换那几行。这意味着网络差的时候它依然打得开，而且放几年不管也不会坏。对一个个人博客来说，
这比我能加的任何功能都重要。

编译交给 [Astro](https://astro.build)。它的 content collections 给每篇文章一份带类型的 schema，
frontmatter 里写错一个字段会直接让构建失败，而不是在页面某处渲染出一个空日期。

## 两种语言，一份代码

站点是双语的。英文在根路径，中文在 `/zh/` 下：

| 路径                   | 语言 |
| ---------------------- | ---- |
| `/blog/hello-world`    | 英文 |
| `/zh/blog/hello-world` | 中文 |

文章就是磁盘上的文件，语言由所在目录决定：

```text
src/content/blog/
├── en/hello-world.md
└── zh/hello-world.md
```

两个文件共用同一个 slug，就被当成互为译文，这足以生成 `hreflang` 标签和每篇文章底部的互链。frontmatter
里完全不记录语言 —— 从路径推导出来，两者就永远不可能对不上。

翻译是可选的。如果只有英文那一份，中文列表就不会列出它，也不会为一个并不存在的页面声明 `hreflang`。

## 字体

拉丁文用 [Newsreader](https://fonts.google.com/specimen/Newsreader)，自托管而不走 CDN ——
少一个第三方请求，而且浏览器缓存分区在好几年前就已经消灭了"CDN 字体能跨站复用缓存"这个理由。中文回退到读者
系统自带的宋体，这样就不必给所有人推送一个几 MB 的 CJK 字体。

两种文字在少数几个地方需要区别对待。中文排得更紧，所以行高放宽、且不做负字距。另外*强调*用的是字下加点，
而不是斜体 —— 合成的倾斜中文实在难看。

> 那些只有真正跑起来之后才会浮现的细节，才是值得写下来的。

## 部署

往 `main` 推一次，就会触发一个 GitHub Actions 流程，把站点构建好并上传到 GitHub Pages。没有需要记住的
构建步骤，也没有需要点来点去的控制台 —— 仓库就是唯一的事实来源，线上跑的就是 `main` 构建出来的东西。
